# Kubernetes Vagrant Playground

This repository is a small playground to spin up a Kubernetes cluster from scratch using **Vagrant** and **Ansible** on top of **Ubuntu 24.04** VMs.

It is meant for local experiments and learning, not for production use.

## Overview

The environment creates:

- **1 control plane node**
  - Hostname: `controlplane`
  - Runs `kubeadm init`
  - Installs **Cilium** as the CNI
- **N worker nodes** (configurable in `Vagrantfile`, default: 2)
  - Hostnames: `k8s-worker-0001`, `k8s-worker-0002`, ...
  - Join the cluster via `kubeadm join`

Networking is handled via a **private VirtualBox network**, with IPs derived from `IP_BASE` in the `Vagrantfile`.

Configuration and provisioning are driven by Ansible playbooks in the `ansible-k8s/` directory.

## Main components

- **Vagrantfile**
  - Defines the control plane and worker VMs, their IP addresses and hostnames.
  - Provisions the VMs using Ansible (control plane and worker playbooks).

- **Ansible roles** (under `ansible-k8s/roles`)
  - **`kube-common`**
    - Disables swap.
    - Installs and configures **containerd**.
    - Configures kernel/sysctl settings required by Kubernetes.
    - Configures Kubernetes apt repositories and installs:
      - `kubelet`, `kubeadm`, `kubectl`, `cri-tools`.
  - **`kube-controlplane`**
    - Runs `kubeadm init` on the control plane.
    - Sets up `$HOME/.kube/config` on the control plane VM.
    - Exports `/etc/kubernetes/admin.conf` to a `vagrant-kubeconfig` file in the project directory and rewrites the API server endpoint to use the controlplane IP.
    - Installs **Cilium** as the CNI plugin.
  - **`kube-worker`**
    - Handles `kubeadm join` for worker nodes.
    - Detects failed or broken kubelet state and performs a cleanup (`kubeadm reset` and removal of stale kubelet config/flags) before re-joining, so a broken worker can be recovered.

- **Playbooks** (under `ansible-k8s/`)
  - `controlplane-playbook.yml`
  - `worker-playbook.yml`

## System requirements

You need the following installed on your **host machine**:

- **Vagrant**
  - Version: 2.2+ (any recent version should work)
- **VirtualBox** (or another Vagrant provider, but this setup assumes VirtualBox)
  - Version: 6.x or 7.x
- **Ansible**
  - Version: 2.12+ recommended
- **kubectl** (optional but recommended)
  - Any kubectl version compatible with the Kubernetes version configured in the `Vagrantfile` (see `kube_version`).

On the host, you should also have:

- A reasonably modern CPU with virtualization support enabled in BIOS/UEFI.
- At least **8 GB RAM** (each VM is configured with 2 GB by default; adjust as needed in `Vagrantfile`).

## Bringing up the cluster

From the repository root:

```bash
vagrant up
```

This will:

- Create the `controlplane` VM and run `ansible-k8s/controlplane-playbook.yml`.
- Create the worker VMs and run `ansible-k8s/worker-playbook.yml` on each.

The Kubernetes version and IP base are configured in the **`Vagrantfile`**:

- `IP_BASE` (e.g. `192.168.99`)
- `kube_version` (e.g. `1.34`)

## Accessing the cluster

After `vagrant up` completes successfully, a kubeconfig is exported to the project directory:

- `vagrant-kubeconfig`

This file is generated by the `kube-controlplane` role by fetching `/etc/kubernetes/admin.conf` from the controlplane and rewriting the API server `server:` field to use the controlplane's private IP.

To use it from your host:

```bash
cd /path/to/k8s-vagrant
export KUBECONFIG=$(pwd)/vagrant-kubeconfig
kubectl get nodes
```

You should see the controlplane and worker nodes in `Ready` state once Cilium and core components are up.

## Common tasks

- **SSH into the controlplane**

  ```bash
  vagrant ssh controlplane
  ```

- **SSH into a worker**

  ```bash
  vagrant ssh k8s-worker-0001
  ```

- **Re-provision only the controlplane**

  ```bash
  vagrant provision controlplane
  ```

- **Re-provision only the workers**

  ```bash
  vagrant provision k8s-worker-0001
  vagrant provision k8s-worker-0002
  ```

- **Destroy the environment**

  ```bash
  vagrant destroy -f
  ```

## Notes and caveats

- This setup is for **local development and learning** only.
- Some tasks (like downloading Kubernetes/Cilium binaries and images) require internet access from the VMs.
- The `kube-worker` role includes logic to reset and re-join a worker when kubelet is in a failed state, but if things get badly corrupted, it may still be easier to destroy and recreate the VM with `vagrant destroy` / `vagrant up`.

## Troubleshooting

- If `kubectl get nodes` from the host fails to connect:
  - Make sure `vagrant-kubeconfig` exists and `KUBECONFIG` is set correctly.
  - Check that the controlplane VM is reachable on its private IP from the host.
- If pods are stuck in `ImagePullBackOff` or similar:
  - Ensure the VMs have outbound internet access to reach `registry.k8s.io` and other registries.
- If workers fail to join or kubelet is in a failed state:
  - Re-run the worker playbook via `vagrant provision <worker-name>`; the `kube-worker` role will try to reset and rejoin the node.
